## 1. 无头模式还是有界面:人工登录时该选哪个

- title: 无头模式还是有界面:人工登录时该选哪个
- url: http://127.0.0.1:8000/articles/headless-vs-headed.html
- summary: Playwright MCP 默认以有界面模式启动，窗口会真的弹出来；无头模式省的是窗口与绘制开销，不是登录时间，两者的 DOM 和网络行为一致。只要任务里含人工输入凭据或验证码，就必须用有界面模式；登录态已存到本地配置或 storage state 后，才可切无头。
- source: 本地练习站（本地练习站 · 浏览器自动化练习用）

## 2. 工具审批:让危险动作真的停下来

- title: 工具审批:让危险动作真的停下来
- url: http://127.0.0.1:8000/articles/tool-approval.html
- summary: 在提示词里写「不许删文件」只降低概率、不提供保证，真正拦得住的是工具层或产品层审批。文中把边界分为三层：allowed-origins 之类的访问过滤（官方明确说它不是安全边界、也不影响重定向）、以 --output-dir 为代表的最小权限工作目录、以及每次敏感动作单独确认的审批层。
- source: 本地练习站（本地练习站 · 浏览器自动化练习用）

## 3. 等待与重试:为什么不能写死 sleep(5)

- title: 等待与重试:为什么不能写死 sleep(5)
- url: http://127.0.0.1:8000/articles/wait-and-retry.html
- summary: sleep 的问题不是慢，而是什么都不保证，要等的是可观察的状态，例如用 browser_wait_for 的 text 等某段文字出现、textGone 等加载提示消失。超时后应重取快照确认结构再重试，重试有 2～3 次上限，到顶就如实记录失败。
- source: 本地练习站（本地练习站 · 浏览器自动化练习用）

## 4. 步数上限:25 次工具调用怎么分配

- title: 步数上限:25 次工具调用怎么分配
- url: http://127.0.0.1:8000/articles/step-budget.html
- summary: 写明步数上限是逼 Agent 在预算内取舍：先保证拿到 5 条有效结果，再考虑优化。典型开销是每篇文章一次打开加一次读取，五篇约十次，加上重新取快照与重试，二十几次刚好够用；到顶必须停止并交出已完成部分。步数上限管整轮次数，超时管单次动作时长，两者都要有。
- source: 本地练习站（本地练习站 · 浏览器自动化练习用）

## 5. output-dir:把 Agent 的写入关进一个抽屉

- title: output-dir:把 Agent 的写入关进一个抽屉
- url: http://127.0.0.1:8000/articles/output-dir-safety.html
- summary: --output-dir 让自动命名的截图和快照都落到指定目录，结果只写这一处，提交时只需看这一个抽屉。注意它只影响自动命名的产物，显式文件名的路径按工作区根解析；往输出目录外写文件属于范围外动作，必须单独确认或直接被拒绝。
- source: 本地练习站（本地练习站 · 浏览器自动化练习用）
