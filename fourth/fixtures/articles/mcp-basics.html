MCP 是怎么把模型和工具接起来的

标签:MCP、基础

MCP(Model Context Protocol)是一套让模型客户端与外部工具服务端通信的协议。它基于 JSON-RPC 2.0,消息格式固定,因此不同厂商的客户端和服务端可以互相拼接。

服务端提供三类能力

第一类是工具(tools),由模型主动调用,例如打开网页、点击元素、读取快照。第二类是资源(resources),由客户端按 URI 读取,更像"提供材料"。第三类是提示词(prompts),由用户主动触发的预设模板。三者用途不同:工具是动作,资源是数据,提示词是交互入口。

三种传输方式

stdio 传输把服务端作为子进程启动,通过标准输入输出交换消息,适合本机工具;SSE 和 streamable HTTP 走网络,适合远程服务。Playwright MCP 默认走 stdio,所以它一般被配置成客户端启动一个命令行进程。

为什么要用协议而不是直接调 API

直接调 API 意味着每换一个工具就要改一次集成代码。有了协议,客户端只需要实现一次,新增工具只是加一条服务端配置。代价是工具描述会占用模型的上下文,工具越多、描述越长,可用上下文越少。

一句话总结:MCP 把"模型能做什么"从代码里搬到了配置里,所以接入新工具通常不需要写代码,但需要在配置里把边界说清楚。
